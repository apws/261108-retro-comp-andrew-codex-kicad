== What the label attachment means

A KiCad net label is an electrical object. Its anchor must touch the intended wire or pin; the nearby text alone does not establish a connection. Matching attached labels can connect physically separate wire groups. Moving a label away from a direct pin-to-pin wire can merely remove a useful name, whereas moving a label that provides the only link can break the circuit.

A crossing, a T-join and a wire endpoint also need different treatment. A dot should represent a real join; a plain crossing should remain unjoined. Native ERC and netlist comparison distinguish an attractive-looking path from a correctly connected one.

The original GIF leaves most address/data connections implicit and visibly draws the scalar support signals. This wired variant makes the A/D groups explicit with native buses and named entries. Standard supply symbols remain appropriate. Its purpose is readable engineering communication as well as a correct machine-readable netlist. Falken emphasized that this visual work is a craft, not a competition with the original drawing or a prerequisite for every future PCB experiment.

== Rechecking later edits

Export the current netlist and ERC report first. A previously reviewed version can be rechecked with the final command below. For a newly edited version, use `--accept-manual` only as part of an intentional review; it records the current hashes only after all checks pass.

[source,shell]
----
kicad-cli sch export netlist --format kicadxml --output output/schematic-wired-a3/Z80_Simple_Computer.xml schematics/02-wired-a3/Z80_Simple_Computer.kicad_sch
kicad-cli sch erc --format json --severity-all --exit-code-violations --output reports/schematic-wired-a3/erc.json schematics/02-wired-a3/Z80_Simple_Computer.kicad_sch
/usr/bin/python3 tools/check_wired_schematic.py
----

These are static electrical/drawing checks. They do not qualify hardware, reset timing or signal integrity.
