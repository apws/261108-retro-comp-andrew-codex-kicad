*Petr, before that had been answered:* If placing the lines nicely is difficult, but the netlist is okay, it is probably not so critical. Visually, recreating that simple schematic with lines would be nicer. As he said, not critical.

*Assistant:* Yes. The chips are connected by net labels, not by lines drawn across the sheet. A label such as `A0` or `/RD` on two pins is the same net. That is what the netlist is checking, and those nets do meet: the address and data buses, the chip selects, and the reset chain.

What you can see as a line is only local. A pin gets a short stub out to its label. A few things are actually drawn: the reset resistor and capacitor, the supply symbols, and the little ground rail on the UART. There is no copper yet. Traces appear only after a board exists and is routed, and this board is still the old file that does not open.

The parts sitting on the red sheet frame are real. Pulling everything inside the border, and drawing the buses as lines the way the GIF does, would only change how the sheet looks. The netlist would stay the same. You said that is not critical, so the sheet was left as it was.

*Petr:* Well, please only then move the parts better on the sheet to fit.

The assistant started that, and did not answer again before the session broke off. From the outside it looked stuck.


== KiCad was open

*Petr:* Excuse me. He had opened the sheet in KiCad. If that is not a problem, he had closed it.

*Petr:* Only now he had closed KiCad entirely.

*Petr:* Please pause and say what the problem was. Was something still locked by KiCad? Is it so hard only to place the symbols closer, so they fit inside? He saved a shot of that wait as `images/261103-0004 very hard for grok only to relayout the sheet QQQ -- Screenshot_20261104_000429.png`.

He then asked to continue, and asked again when the reply had still not come back.

*Assistant:* Nothing is locked. KiCad is closed, and the sheet on disk is already the moved one. Reopen `Z80_Simple_Computer.kicad_sch`.

The lock was only the editor holding the file. While the schematic was open, KiCad kept `~Z80_Simple_Computer.kicad_sch.lck`. Writing the file then would have been thrown away the next time that window saved. Closing the sheet released that lock. The project window staying open after that was not what held the parts in place.

Sliding the symbols is not electrically hard. This sheet is joined by net names, not by long wires, so a part can move without the nets changing. That checked out: same 102 nets, same 33 parts, names included. The electrical rules check is still clean, 0 errors and 0 warnings.

What was awkward was fitting the paper, not the circuit. Only three things hung outside the red frame.

* The blue note at the top left. With no alignment set, KiCad anchors that text at its center, so a note placed near the corner drew leftward off the page. It is now anchored at its bottom-left corner, inside the frame.
* The three charge-pump capacitors beside the MAX232, which sat past the right edge.
* The reset switch, whose ground symbol just touched that same edge.

Pushing the whole right-hand side left by the same amount would have dropped the reset capacitor on top of an OR gate. So the parts that were already inside stayed put. The MAX232, its capacitors, and the DE9 connector moved left together by 25 mm, and the switch moved left by 10 mm. A plot of the page shows all the ink inside the frame.

The positions live in `tools/build_schematic.py`, which rewrote the sheet. The guide already says this: if you drag a part in KiCad and then run that script, the script wins.
